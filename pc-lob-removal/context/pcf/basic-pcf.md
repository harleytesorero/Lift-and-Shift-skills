# PCF File: Technical Description

## Overview
A Page Configuration Format (PCF) file is an XML-based file format used by Guidewire InsuranceSuite applications (PolicyCenter, ClaimCenter, BillingCenter, ContactManager) to define and render the user interface — screens, panels, pages, and their interactive elements. 

## File Format and Root Structure
A PCF file is an XML document. The root element is <PCF>, which wraps one or more top-level UI constructs such as <Page>. Embedded Gosu code blocks appear within <Code> elements using CDATA sections. A minimal structural skeleton looks like:

```
<PCF>
  <Page ...>
    <Code><![CDATA[
      // Gosu logic here
    ]]></Code>
  </Page>
</PCF>

```
The ```<PCF>``` root element closes the document, and the ```<Page>``` element (or equivalent structural container) closes immediately before it. 
 

## Element Types
PCF files contain three fundamental categories of elements: 

- ** Physical elements — Widgets with a direct visual presence in the rendered UI, such as buttons and input fields.
- ** Behavioral elements — Non-visual elements that govern the behavior of other elements, such as iterator sorting and client reflection directives.
- ** Structural elements — Grouping constructs that organize other elements without themselves representing a single UI component; examples include panels and screens.

## Element Nesting and Containment Rules
PCF elements follow a strict containment hierarchy. InsuranceSuite enforces valid nesting: the editor does not permit inserting elements that are invalid for a given page or grouping context. 

The hierarchical containment of elements is visible in Guidewire Studio's Structure tab, which provides a tree view of the PCF element hierarchy on a page. 

## Embedded Gosu Code
PCF files support inline Gosu scripting via <Code> elements with CDATA blocks. Gosu is the programming language used for PolicyCenter (and broader InsuranceSuite) business logic, rules, and configuration scripting. 

## File Naming Conventions
For PCF files not generated by APD (Advanced Product Designer), filenames must end with the PCF element type. Two naming forms are accepted: 

Prefix form: ```<CODE>_<PCFName><PCFType>.pcf```
Suffix form: ```<PCFName>_<CODE><PCFType>.pcf```
Example: ```AUCL_StagedMsgSearchScreen.pcf```

## File Organization and Directory Structure
PCF files are organized in a hierarchical folder structure within Guidewire Studio. Folder names are case-insensitive and must be unique within the hierarchy. 

For Advanced Product Designer (APD)-generated products, PCF files are placed in subdirectories under PolicyCenter_installation/modules/configuration/config/web/pcf/. Generated file types include screen files (e.g., YYYRiskScreen.pcf), panel set files (e.g., YYYRiskPanelSet.pcf), popup files (e.g., YYYRiskPopup.pcf), and policy file configurations (e.g., PolicyFile_YYYRisk.pcf). 

## Widget Identification
Guidewire strongly recommends assigning unique IDs to all widgets defined within a PCF file, to ensure widgets can be reliably identified and referenced later.
